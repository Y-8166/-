# 信息图形：数据逻辑 × 类型案例知识库

> 状态：**v0.2.0 课件校订版（2026-11-19）**。已获得用户上传的73页《第三讲—信息图形类型学(2)》，据此整理16条课件缩图观察记录。它们仅支持可见形式的初步分析，尚无原作品高清源数据；五种数据逻辑定义是经课件对照的工作模型。

本仓库研究的对象是具有**数据/信息组织、视觉编码、阅读路径、叙事意图**的信息图形（infographics）。目的是从用户持续提供的案例图中归纳结构性规律，并在真实证据积累后更新分类概念、视觉设计原则和制作方法。

## 两套分类轴：不可混为一谈

| 层次 | 回答的问题 | 当前分类 | 位置 |
| --- | --- | --- | --- |
| **数据逻辑**（结构轴） | 数据为什么被这样组织，关系的本质是什么？ | 编年、层级、编目、字母表、地理 | [`01-信息图形数据逻辑/`](01-信息图形数据逻辑/) |
| **表现类型**（呈现轴） | 作品如何把信息转化为可阅读、可叙事的页面？ | 课件第22–38页的16种表现类型（含混合、列表、时间轴、示意、流程等） | [`02-信息图形类型案例/`](02-信息图形类型案例/) |

**多对多关系**：一份时间轴作品常采用编年数据逻辑，也可能以地理或层级信息为辅；混合型作品可以叠加编目、地理和编年逻辑。不能仅凭画面形态判断数据的本质，也不能把“时间轴型”等同于“编年型”。

每件作品在 01 的五类中登记一项主导关系，可记录辅助逻辑。02 的表现标签用于说明画面怎样组织和被检索，允许主标签和辅助标签。ISOTYPE、统计图形与 Gestalt 分别记录图符转译、数据计算与知觉组织，可按案例证据跨章节引用。

## 文档维护原则：原位更新，不新增 Markdown 文件

**用户确定的规则（2026-11-19）**：后续每次补充案例、纠错、核实或完善方法，**优先且只修改仓库中已经存在的 Markdown 文档，不因更新而另建说明文档、案例记录文档或“新版”副本**。历史 CASE-0001–0016 文件保留原路径；若原案例有新证据，直接修订对应旧 CASE 文件。若是全新案例，分配新的 CASE ID，直接追加到已有的 [`案例索引`](02-信息图形类型案例/案例索引.md) 及相关表现类型说明，必要时同步修改五种数据逻辑定义。新案例图片可以按 CASE ID 放入原有 `案例图/` 图片目录，但不为其新建 Markdown 文件。如需确实新增研究主题或文件结构，应先获得用户明确同意。

**Git 提交会保留历史版本**，因此不通过 `-v2`、`-修订版` 等命名生成副本。每次提交前检查现有文件与链接；修改旧内容、添加段落或更新图像引用后再提交。

## 每收到一张案例图的更新程序

1. **登记来源**：分配不可变 ID（`CASE-0001` 起）；记录图片出处、作者/机构、时间、用户提供时间、版权及是否有可核验数据。
2. **分开记录证据**。标注原图或缩图来源，区分源表数据、图面转录、图面量测、计算结果及待核项。仅有缩图时先记录可辨认的图面事实。
3. **双轴编码**：判别 1 个主导的数据逻辑（必要时附多个次级逻辑）及 1 个主表现类型（必要时附次类型），说明判定依据与可能的替代解释。
4. **沿 A–E 分析并留下复核材料**。在原记录补充一行的记录粒度、字段、单位和来源。计算结果注明输入与公式。确有可复用数据且使用权限明确时，附源表链接或 CSV。详见[案例分析模板](02-信息图形类型案例/案例分析模板.md)。
5. **更新案例类型文件**：在对应标签目录的 `案例/README.md` 加入索引条目，观察与分析写入原案例记录或 `00-标签说明.md`。样本不足时不将单一案例升格为通用原则。
6. **更新数据逻辑文件**：只修改被案例证据支持的条目；优先通过相对链接指向 `02/案例索引.md` 的新条目或已存在的 CASE 档案（只更新现有文档）。`01/` 永远不放图像。
7. **保留修订依据**：在文档修订记录中写明日期、CASE ID、变更类型（新增/修订/反例/撤回）和理由；提交 Git 变更。

> “实时更新”在本项目中指**每次新增案例并进行分析后即更新知识文档**，而非没有触发条件的后台自动写作。仓库加入了自动链接与目录校验，提交时会检查结构；是否采纳概念修订仍需以案例证据判断。

## 研究与设计共通规则

- **可核算**：统计图形应标注指标、单位、分母、统计时间窗、数据来源，必要时列出公式。
- **结构与编码配合**：先确定数据关系，再选择位置、长度、角度、面积、颜色、图标及布局；装饰不能替代定量编码。
- **防止语义偷换**：把等级误写为时间、把枚举误写为排名、把地理面积误当数据量，均属于错误编码。
- **证据等级**：`理论假设` → `单例观察` → `跨例反复出现的模式` → `具有反例边界的设计原则`。不要跳级。
- **异议与反例**：为相反案例保留解释和修正规则，不能只收集支持已有分类的作品。
- **版权与隐私**：仓库已收录用户提供课件中16张缩略图作案例对照，附课件页码；这不等于对原作品获得独立转载或商业使用授权，对外继续传播需核实版权。

- 课件第6页在“层级型”标题下重复了编年型的“单向、不可逆、顺序排列”措辞；仓库依据父子/包含关系独立界定层级而不沿袭该句。
