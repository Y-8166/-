# 案例记录说明

此目录用于逐图分析的 Markdown 文件；图片在同级 `../案例图/` 内，**不得放到 `01-信息图形数据逻辑/`**。

## 新增单个案例

1. 复制 [案例分析模板](../案例分析模板.md) 到 `CASE-0001-简短标题.md`，替换案例 ID 与元数据。
2. 保留原始图片证据：如获得合法授权可存至 `../案例图/`；否则仅保留可靠的外部图像 URL 及来源说明。
3. 先在 A–E 表格填写**可见事实**，随后填写合理解释、可迁移方法与风险，不反过来让理论强迫案例归类。
4. 在 [案例索引](../案例索引.md) 登记分类与分析状态；在相关类型说明中增加带 Markdown 链接的案例记录。
5. 如需要更新 `../../01-信息图形数据逻辑/` 下的定义，在修改条目后附 `[CASE-0001](../../02-信息图形类型案例/案例记录/CASE-0001-简短标题.md)` 类似链接（该路径只是**示例**，在真实文件存在后才加入）。
6. 通过 `python ../../scripts/validate_repo.py` 检查链接，并在 Git commit 中说明修改的定义与依据。

## 不可省略的证据纪律

- **观察事实 / 解释性判断 / 建议方法**要分开写；图内不可读的具体数字不得猜测。
- 一个案例可能有多种合理分类，主次都可记录，但不应每出现一个标签就算一个独立样本。
- 新发现的“设计方法”先标记**案例特征**，累积多种不同作品之后才能升级为通用原则。
- 同一原则有反例时保留反例并注明适用边界，不可直接删除不利样本。
- 不能从用户提供的图片擅自推断作者身份、制作动机和原始数据采集方法。
